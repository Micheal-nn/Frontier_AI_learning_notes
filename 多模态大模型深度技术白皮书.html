00 /先看时间线：典型模型如何走到多模态统一

以下按论文首次公开的年/月排列，而非当前 PDF 修订日期；“里程碑”是本文选取的代表性设计节点，不是按性能排序，也不意味着后者全面取代前者。视觉理解和视觉生成两条线先并行发展，2023–2024 年出现图文混排与统一 token 路线。[1][15]

2020

ViT（Vision Transformer，视觉 Transformer）：把图像切为 patch 序列，形成后续视觉编码器基座。

2021

CLIP（Contrastive Language–Image Pre-training，对比式图文预训练）：大规模图文对比学习；LDM（Latent Diffusion Model，潜空间扩散模型）：降低图像生成成本。

2022

BLIP（Bootstrapping Language–Image Pre-training，自举式图文预训练）：清洗噪声图文数据，统一理解与文本生成。

2023

BLIP-2 → LLaVA → MiniGPT-4 → Emu → Qwen-VL → VideoPoet：LLaVA = Large Language and Vision Assistant（大型语言与视觉助手）；GPT = Generative Pre-trained Transformer（生成式预训练 Transformer）；Qwen-VL 中 VL = Vision-Language（视觉语言）。这一年从冻结桥接、视觉指令调优，走到混排与视频生成。

2024

Chameleon → OneVision → CogVideoX → Qwen2-VL → Emu3 → Janus：早期融合、动态分辨率、视频扩散与统一视觉生成分叉。

2025

LLaVA-OneVision-1.5：更完整的开放训练配方与视觉数据治理，但仍属于理解型模型。

2026

Qwen3.5 / OneVision-2 / MiniCPM-V 4.7：混合注意力、视频稀疏 token 与早期视觉压缩，详见后文官方仓库对照；时间线主体仍按原始论文节点排列。

任务地图 /六种输入→输出范式：区别不在“能读图”三个字

约定 T=文本，I=一张或多张图像，V=带时间顺序的视频；箭头左边是条件输入，右边是需要真正生成的输出。例如“视频→文字”不因为回答附带一张上传的缩略图就变成“视频→视频图文”；只有新生成或编辑的图像/视频进入结果，才算右侧视觉输出。六类是能力/产品任务分类，不是六种相互排斥的模型架构：一个统一模型可能覆盖多类；单一流水线也可串接多个专用模型。[15][19]

关于“图文”的口径

“文→图文”指生成新的图片并与生成文字混排，不是文→单图后在 UI 旁放回原提示词；“视频图文→视频图文”也要求生成或编辑新视频。能否同一次解码原生交错输出，必须分别核对论文与部署接口。任务矩阵和工程串接建议是本文归纳，不能反推某篇论文覆盖全部六类。

Ⅰ｜图文 → 文：读图回答和证据抽取

I + Tprompt → Tanswer

典型任务：“维修单的设备编号是多少？请注明所在区域。”图像经 ViT/CLIP/SigLIP/动态视觉编码器转为 patch 特征；投影器、Q-Former 或 patch merge 将其送入 LLM，文本 decoder 预测答案。训练重点是正确图文配对、局部细节与答案区域的交叉熵（CE）mask。LLaVA 的简洁投影、BLIP-2 的查询压缩与 Qwen2-VL 的动态分辨率，都在取舍视觉细节、上下文长度和训练成本。[6][8][12]

架构边界与验收：模型会“看”也会“写”，但只有词表解码器，无法凭相同输出头生成像素。对于 OCR/表格，要检查 crop 后文字是否仍清晰；对于图片幻觉，以遮挡证据/替换图片的反事实样本验证视觉依赖。工程上优先把图像 token 展开与文本 mask 对齐，再做模型升级。

Ⅱ｜文 → 图文：带插图的文章、故事和教程

Tprompt → (T₁, I₁, T₂, I₂, …)

与纯文→图不同：输出的文字、图片位置和引用关系本身就是目标。统一自回归路线将图像压为离散视觉 token，图文共享序列和边界标记；p(z₁,…,zₙ | T) = ∏ p(zₖ | z<ₖ,T)，预测视觉 token 后由视觉 tokenizer 的解码器还原像素。Chameleon 支持任意顺序图文输入/生成；Emu 使用下一文本 token 分类或下一视觉 embedding 回归以支持混排上下文——两者建模方法不完全相同。[17][19]

组合路线：LLM 先输出结构化段落、插图提示和图号，再由条件扩散图像模型生成 I₁…Iₙ 并插回正文。LDM 在自编码器潜空间去噪，用 cross-attention 注入文本条件；组合系统还需解决人物跨图一致、引用编号、失败重试与段落-插图对齐。[16] 这是工程编排，不是 LDM 单独能生成文章。

Ⅲ｜图文 → 图文：看原图后编辑并解释

Isrc + Tedit → Idst + Texplain

典型任务：“保留原图人物和构图，把背景改成雨夜，并解释改动。”理解型主干抽取原图对象/区域；图像生成器以原图 latent、mask、边缘/深度或参考特征为条件生成目标图；文字端说明修改内容。若用统一 token 模型，需在交错序列中同时学习读入原图、生成新图和继续文本。Chameleon 是图文混排代表，但其论文不保证任意高精度局部编辑开箱可用；Janus 将理解与生成视觉编码器分开，缓解语义编码与像素重建的目标冲突。[19][22]

损失和验收：组合式编辑用原图条件的去噪/flow 目标，另以 CE 训练解释；关键约束是未编辑区域、身份、版式和文字保持。简单文生图会“重画整张”，难保证原图保真；工程门禁建议分目标/非目标区域抽检，而不只看整体美感。

Ⅳ｜视频图文 → 文：理解动作、事件与时间顺序

V0:F + Iref + Tquestion → Tanswer

信息流：视频先按时间戳抽帧/分块，每个帧（可附参考图）送入视觉编码器，视觉 token 带帧序、二维位置及时间信息，再同问题进入 LLM。LLaVA-OneVision 在单图/多图/视频间做任务迁移；Qwen2-VL 的 M-RoPE 显式表示时间、高和宽的位置。它们输出文字，不是视频。[9][12]

真正难点：取样频率过低会漏掉短动作，频率过高则令视觉 token、prefill 和 KV 成本上升；可先粗采样定位时间窗，再针对相关片段细采样，但必须把时间戳映射回原片源。训练以带帧序/时间标注的 QA、事件顺序和证据引用为主；评测要打乱帧序、替换关键帧，并分别测时间定位与回答事实性。参考图作为额外输入时，要防止把它误当视频当前帧。

Ⅴ｜文 → 视频图文：把脚本变成连续画面和说明

Tbrief → Tscript + Vgenerated + Ikeyframes

区别于上类：此时要生成新的时空信号。CogVideoX 路线先以 3D VAE 压缩时间与空间，把随机噪声潜变量交给文本条件扩散 Transformer 迭代去噪，最后解码视频；VideoPoet/Emu3 则把视频压为离散 token，由自回归模型预测后解码。两者均面临人物/背景跨帧一致性、运动合理性、长度/帧率与显存约束。[18][20][21]

文字也必须产生：生成器输出视频不等于自动输出脚本和解说。实际产品可让 LLM 先定镜头与分镜编号，生成器逐镜头出视频、选取关键帧，最后核对旁白与成片一致；这是组合式架构。VideoPoet 论文明确表示其文本生成能力未被专门评估，不能把它作为单模型“文→视频图文”已验证能力。[18]

Ⅵ｜视频图文 → 视频图文：理解原片后有约束地改片

Vsrc + Iref + Tedit → Vdst + Ipreview + Treport

典型任务：“保持镜头运动和人物身份，把傍晚场景改成下雨，同时给出修改清单。”输入不只是文本：源视频潜变量/离散 token、首帧/参考图、mask、光流、深度、时间窗、指令都可能参与条件。VideoPoet 论文研究了视频补全、外扩、风格化和视频到视频链式编辑；其文字说明的自动生成仍需额外组件或专门训练。[18]

两类技术路径：自回归视频 token 预测将保留的原片片段作前缀或条件，模型补齐目标序列；条件视频扩散在源潜变量/掩码约束下去噪，保持未编辑区域。为确保“仅改变该改变的”，工程上还需要对象跟踪、跨帧 mask 一致性、时间戳对齐、身份/背景保持和局部编辑强度控制。输出的摘要与关键帧必须回看实际生成的视频，不能只根据原始编辑意图撰写。

选择架构前要问的四个问题

  1. 输出要求：新图片/视频是否必须生成？若是，仅有视觉 encoder + LLM 不够，必须有图像/视频 tokenizer + decoder 或扩散/flow 解码路径。
  2. 保真约束：要不要保持输入人物、构图、文档字段、动作轨迹？有约束的编辑不同于无条件重画。
  3. 时间与长度：视频的帧数、帧率、持续时间是否固定？理解侧主要消耗输入 token，生成侧还要付出时空潜变量建模和多步采样。
  4. 输出耦合：文字、图片/视频是否必须在一次端到端解码中彼此引用？若否，分工明确的组合式流水线往往更易校验、缓存和回滚。

01 /范式跃迁：问题定义与技术演进

给定图像 I、文本指令 x，理解型多模态模型学习条件分布 p(y | I, x)：视觉编码器把像素变成特征，连接器决定多少、以什么形式进入 LLM，LLM 以自回归方式输出文本。共享嵌入空间不等于完整的视觉理解：图文检索只需辨别整体语义，OCR、定位、图表问答还要求局部细节、几何位置和证据链。综述将架构、训练数据、评测与幻觉列为不同层面的问题。[1][2]

1.1 纯文本 LLM 与视觉语言模型：不是“一路对多路注意力”

注意力头的数量不等于输入模态的数量。纯文本 LLM 也有多层、多头因果自注意力：每个头各算一组 Q/K/V，头在同一层并行，再经输出投影汇合。Qwen2-VL 则在这个语言解码器前增加一套视觉编码器：视觉 patch 在 ViT 内通过多头自注意力交互；随后相邻 patch 合并并投影到语言维度；语言解码器对“文本嵌入 + 视觉嵌入”的同一序列做因果自注意力。视觉编码先于语言 prefill，而不是图像、文本各自有一个独立 LLM 同时给下一词投票。[12][23]

02 /核心数学：从注意力到条件生成

2.1 注意力的“看见范围”由掩码决定

在每个头内，查询 Q 与键 K 做点积，按 √dₖ 缩放，再由掩码 M 决定允许读取的位置，最后对值 V 求加权和。ViT 通常允许同一图像 patch 互相读取；语言 decoder 只能读取当前位置及之前的多模态前缀。两者数学算子相同，训练目标与可见性不同。某些模型采用窗口、稀疏或线性注意力，不应把一次全局 n×n 矩阵当作所有实现的固定成本。[4][12]

Attention(Q,K,V) = softmax(QK⊤/√dk + M)V；Npatch ≈ (H/p)×(W/p)计算示例：224²、p=14 → 256 patch；448² → 1024 patch。标准密集注意力的两两比较增加 16 倍，但端到端延迟不能据此直接乘 16；FlashAttention 改善实际显存占用，不改变密集注意力比较量的阶。

2.2 三种损失各回答一个问题

目标监督信号适用与边界
CLIP 图文对比一批图文的配对索引；双向交叉熵学习全局相似性，适合检索/零样本分类；不直接训练长答案或局部 OCR。[3]
图像条件 SFT只在助手答案位置算 next-token 交叉熵学习“看图后如何回答”，必须核对图像占位符、label mask 和反事实视觉依赖。[8]
视觉生成离散图像/视频码的 next-token CE，或连续潜变量的条件去噪/flow还要有可重建 tokenizer/VAE 与视觉解码器；文字答案损失不会生成像素。[16][21]
LITC = ½[CE(S,diag)+CE(S⊤,diag)]；LSFT = −Σt∈答案log p(yt|I,x,y<t)对比相似度 S 来自图文双塔；SFT 的图片 I 实际经 processor/视觉编码/连接器成为连续向量。ITC 的“同批其他样本”可能有假负例，不能把增大 batch 当作必然精度收益。

2.3 一个视觉 token 不是一个像素，也不是一个文字 ID

连接器输出的视觉向量与文本 embedding 具有同一隐藏维度，但视觉向量不必有对应的词表 ID；处理器会按图片网格展开图像占位位置。语言层将其与文字一起视作已知前缀，因果注意力可从后续问句/输出位置读取此前的视觉 K/V。若占位位置数与视觉特征数不一致，Qwen2-VL 的参考实现直接报错，而非自动对齐。[23]

2.4 图像/视频输出需要不同的解码目标

离散路线先训练可重建的视觉 tokenizer，把图像/视频变成码本索引，再对混排 token 做自回归预测并解码；扩散路线先用 VAE 压缩目标，随机加噪并训练条件网络预测噪声/速度等，推理时经多步迭代再解码。Janus 分开理解与生成视觉路径，原因正是“读懂语义”与“还原像素细节”的训练诉求不同。[16][22]

zt=√ᾱtz₀+√(1−ᾱt)ε；Lε=E‖ε−εθ(zt,t,c)‖²仅展示一种噪声预测目标；CogVideoX 等具体实现需核对参数化。c 可含文本、原图 latent、mask 和参考帧。视频生成的 3D 潜变量、步数与帧数开销不能用理解型 LLM 的 KV 公式代替。

2.5 实用算力直觉

理解型的总预算包括媒体解码、视觉编码、合并后的视觉 token 与 LLM prefill/decode；视频理解还乘以帧数/采帧策略。若从 224² 切换到 448²，视觉 patch 变 4 倍，2×2 合并后进入 LLM 的视觉位置也变 4 倍；但延迟受内核、批量、文本长度等共同影响，必须实测。长视频生成另需时空潜变量、VAE 解码和生成步数。[12][20]

03 /核心架构：逐层拆解与张量路径

3.1 视觉编码器：先保留可用的局部证据

ViT 将 H×W×3 像素投影为 [Npatch,Dᵥ] 并加入二维位置，堆叠注意力与前馈块；CLIP 的对比目标使全局图文语义可比较，但仅取一个全局向量会损失小字与区域关系。Qwen2-VL 保留变长 patch，经 2×2 merger 把邻接局部特征送入语言维度；详细数值见3.8。[3][4][12]

3.2 连接器：压缩率决定保留哪些证据

架构视觉读取/映射算子主要交换
LLaVA逐 patch 线性/MLP 投影路径简单，输入视觉位置多；高分辨率带来 prefill 开销。[8]
BLIP-2可学习 query 对视觉 patch 做交叉注意力长度近固定，语义筛选强，但小字/定位可能在瓶颈处丢失。[6]
Qwen2-VL邻接 2×2 特征拼接再 MLP长度随有效图像尺寸变化，压缩比约 4:1；必须限制最大视觉 token。[12]
MiniCPM-V 4.7在 ViT 中较早进行混合 4×/16× 压缩后续视觉计算更省，压缩程度影响细字保真；需按任务评估。[29]

3.3 Q-Former：为什么不是“一个池化层”

BLIP-2 冻结预训练图像编码器，Q-Former 含可学习 query、自注意力以及插入的图像交叉注意力；文本分支与 query 分支共享部分权重，依据任务切换可见性掩码。第一阶段以图文对比（ITC）、图文匹配（ITM）与图像条件文本生成训练视觉表示；第二阶段将 query 输出投影到冻结 LLM 的输入空间，训练图像条件文本生成。论文实验使用 32 个 query，每个 768 维；这是特定实现，不是 Q-Former 定义。[6]

3.4 动态分辨率与时空位置：Qwen2-VL

Qwen-VL 的图像路径有固定尺寸约束，Qwen2-VL 引入动态分辨率：处理器按像素范围调整有效宽高、对齐 patch 网格，视觉 ViT 用 2D-RoPE 表示行列；语言侧 M-RoPE 把位置拆成时间、高、宽三个分量。224×224,p=14 的整齐尺寸算例对应 256 patch、合并后 64 个视觉向量，再加边界标记共 66 个视觉段位置；不能将此例当作线上默认值。[11][12]

视频先解码/采帧，时间 patch 与空间 patch 共同进入视觉路径；并非每层 ViT 必然对整段影片做全局注意力。M-RoPE 让语言 decoder 在已知前缀中区分“哪一帧、哪一行、哪一列”。工程要保留原始时间戳、裁切映射和视觉 token 上界，防止区域定位看似正确却落在错误帧。[12][23]

3.5 融合边界：理解型只有文字输出头

在 Qwen2-VL 里，视觉编码器输出的连续向量替换语言序列中的图像占位嵌入；decoder 统一对可见前缀做因果注意力，经 lm_head 产生文字词表的 logits。“会看图”与“会生成图”是不同接口：Janus-Pro 另外训练生成视觉 token 与解码器；CogVideoX 另外训练条件视频扩散。通用 LLM 的文字输出头不能靠改 prompt 输出像素。[23][33][20]

先限定 token 的含义：图片文件不是一个 LLM token；视觉编码器产生多个 patch 特征，桥接器压缩/映射后形成若干连续向量，占据语言序列里的若干位置。下图追踪的是“下一个输出文字 token”的查询如何使用这些视觉向量；它不是把某个像素逐层变成一个汉字。多头注意力在纯文本 LLM 里也存在；多模态新增的是非文本输入的编码、位置、融合和有时额外的输出解码器。[12][23]

推理时序：① CPU/设备解码图片并整理 prompt；② GPU 上视觉编码和连接器产生视觉嵌入；③ 一次 prefill 对文本+视觉序列执行 LLM 各层，写入 KV cache，并用最后一个已知位置的 hidden 得首个输出分布；④ 每生成一个文字 ID，把它作为下一轮已知输入，仅让这个位置穿过各层并查询已有 K/V；⑤ 输出终止或达到上限。不存在先放一个空白答案 token 再读未来答案的步骤；真实回答依赖多个视觉位置与文字位置的联合上下文。[23]

3.8 Qwen2-VL-7B-Instruct：从像素到下一个字的算子级追踪

版本边界：下面以原始 Qwen2-VL 论文、官方 Qwen/Qwen2-VL-7B-Instruct 模型卡和 Transformers v4.46.3 实现为参照，分析图像/视频输入→文本输出；不把 Qwen2.5-VL、Qwen3-VL 或所有推理框架的实现细节混成一套。与早期 Qwen-VL 的位置感知 cross-attention adapter 不同，此版视觉连接器的主要算子是相邻 2×2 patch 合并后的 MLP。具体形状应以权重配置和 processor 输出复核。[11][12][23][24]

阶段与算子形状 / 结果必须理解的边界
① 解码、EXIF/色彩与 resize/normalize有效 H'=W'=224，图像网格 grid_thw=(1,16,16)原图可以不是 224；processor 约束总像素并把宽高对齐到 28 的倍数。单图在该实现中沿时间维复制成 2 帧，供 temporal patch=2 的 Conv3d 消费。[23][24]

③ 视觉块：LayerNorm → QKV Linear → 2D-RoPE → 缩放点积注意力 → 投影/残差 → LayerNorm/MLP[256,Dᵥ]，长度暂不变视觉 patch 在各图/帧片段内双向交互；cu_seqlens 隔开不同视觉片段。FlashAttention/SDPA 是同一语义的不同内核，不是额外增加一条注意力路。[23]

⑥ 语言 decoder：M-RoPE → RMSNorm → GQA 因果注意力 → FFN → 词表 Linear[B,L,Dₗ] → [B,L,Vocab]；取下一个文本 token先 prefill 全部文本+视觉嵌入，再增量 decode；视觉编码不在每个新文字 token 上重跑，语言侧 K/V 逐步缓存。[23]

再看变长：同样的单图若有效尺寸变成 448×448，视觉 patch 为 32×32=1024，合并后 256 个视觉嵌入（另有视觉边界 token）；这解释了分辨率上升为何主要冲击视觉编码、语言 prefill 与 KV，而不是每一步 decode 都重算 ViT。该数字是由 patch/merge 参数推算的整齐尺寸示例；实际尺寸、图片张数、视频时间采样和模型版本须以 image_grid_thw 与模板展开结果验证。[12][23]

视频版本多一步时间索引

视频样本变为 grid_thw=(T,H/14,W/14)；PatchEmbed 的时间核覆盖 2 帧，视觉注意力按实现的 cu_seqlens 在时间 patch 对应的视觉片段内计算；语言侧 M-RoPE 为视觉嵌入提供时间、高、宽三组位置索引。不要假定视觉 ViT 对整段视频跨所有帧做一张全局注意力矩阵，也不要把“跨帧信息”误解为新建一个文本解码器。输入采样的时间戳和帧率仍是 processor/服务层契约。[12][23]

架构评审的四个问题

① 输入如何编码、输出由什么解码？② 文本/视觉/视频分别用什么训练目标？③ 原图/原视频哪些区域与时刻必须保真？④ 最差输入输出长度下，视觉 token 或时空潜变量预算是多少？把这四项连起来，才谈得上模型、数据与服务的共同选型。

04 /完整训练调优：数据 → 对齐 → 指令 → 验收

“四阶段”是便于工程组织的参考路线，不是每篇论文都按同样顺序训练。LLaVA 采用特征对齐、视觉指令调优两阶段；BLIP-2 两阶段都服务于冻结主干桥接；Qwen2-VL 使用三阶段；OneVision-1.5 划分 alignment、mid-training、instruction tuning，随后有可选 RL。阶段名称相似但模块冻结范围与目标函数不同。[6][8][12][10]

4.0 数据先行：图像、问题、答案及位置必须对齐

一条样本至少保留媒体哈希、来源/授权、宽高/时长、任务类型、问题、答案、对话模板、分割集与标注质量；定位任务还要记录坐标系，视频还要保留原始时间戳和采样策略。图片近重复和同实体跨训练/测试泄漏会让指标虚高；网页图文配对的 alt text 未必描述画面。BLIP 的 CapFilt 是清洗噪声配对的一种方法，不等于所有合成描述都可靠。[5]

分层训练目标与参数范围通过条件 / 排查
4.1 桥接对齐已有图像编码器与 LLM；冻结双主干训练投影器，或按 BLIP-2 方法训练 Q-Former 的 ITC/ITM/文本生成目标。替换图片后答案应跟着变；若不变，先查媒体加载、占位展开、mask、可训练参数。[6][8]
4.2 多任务中训按图文描述、OCR、图表、定位、多图/视频设置采样与 loss；需要新视觉细节能力时才解冻 ViT 高层或全模型。同时记录样本数与实际视觉 token 数，防止长视频占据绝大部分计算；检查文本回归与小目标能力。[10][12]
4.3 指令调优用与推理相同的 processor/template；仅对需要预测的助手答案标注交叉熵，其余位置设 ignore_index。一条样本打印 input、展开后的视觉位置、答案标签和长度；不能把提示词或 padding 错算入目标。
4.4 偏好/RL（可选）DPO 的偏好答案必须共享同图同问；可验证任务才考虑用 GRPO 类奖励优化。若出现奖励投机、图像依赖减弱或短回答退化，回退 SFT checkpoint；不要把 RL 视作所有模型的必经阶段。[10]

按模型拆解：训练阶段相似，更新范围不同

BLIP-2 的第一阶段在冻结视觉骨干上训练 Q-Former 的图文对比/匹配/条件文本目标，第二阶段让 query 输出适配冻结 LLM；LLaVA 的两阶段是简单连接器对齐和视觉指令调优；Qwen2-VL 论文的三阶段依次侧重 ViT 视觉预训练、解冻全参数的多任务学习、冻结 ViT 的指令微调。OneVision-1.5 的 Stage-1.5 使用全参数中训，不可被误写为“始终冻结主干”。若目标是票据 OCR，先判断数据与分辨率能否覆盖小字，再决定是否解冻视觉层。[6][8][10][12]

有效 batch = 单设备样本数 × 数据并行副本数 × 梯度累积；损失只在被监督的答案 token 位置计算多图与长视频的计算成本不能只看样本数：同时记录各任务的视觉 token、答案 token、每步显存峰值与梯度范数。packing 时需验证跨样本 attention 隔离和每样本位置/媒体索引。
一个训练调试闭环

用同一张图做原图、遮挡关键区域、随机换图三种输入：若答案都相同，优先检查视觉路径/模板；若细字错而裁切放大后正确，优先改预处理和像素预算；若图文正确却文字能力退化，检查解冻范围、数据配比和学习率，而不是直接增加 RL。每阶段保存权重、processor、tokenizer、数据版本、采样策略和随机状态，断点续训时核对学习率及样本顺序。

4.5 生成图像或视频：另建可重建输出路径

图文→图文不能只微调 Qwen2-VL 的文字头。统一离散路线需可重建视觉 tokenizer、视觉码监督与图像解码器；扩散/flow 路线需目标图/视频的潜变量、条件和去噪目标。训练还要针对未编辑区域、身份、文字、视频时间一致性设置回归集；是否把文字解释放在同一次解码，取决于实际模型与产品编排。[16][20][22]

06 /推理部署：token、显存、延迟与故障

6.1 先算最坏视觉 token，再估 KV cache

部署时统一预算：Ntotal = Nsystem + Nuser + Nvisual + Nhistory + Noutput。文本化图像占位符个数不等于视觉展开长度；processor 的 patch/crop/frame/merge 策略才是决定量。Qwen2-VL 类变长输入要以实际上线预处理跑 p50/p95/p99 token 分布，并按最坏业务输入做容量门禁。[12]

KV 字节 ≈ B × L × (Tprompt + Tgenerated) × 2 × Hkv × Dhead × byteskvB 为并行序列数，L 为 LLM 层数，Hₖᵥ 为 KV 头数；2 代表 K/V。与 GQA/MQA、KV 精度、页式内存管理和分布式切分有关；不含视觉编码器、权重、激活、碎片与框架预留。

纯计算示例：假设 B=1, L=32, Hkv=8, Dhead=128, bytes=2，每个 LLM token 约消耗 32×2×8×128×2 = 131072 B ≈ 128 KiB KV；若新增 1024 个视觉 token，新增约 128 MiB KV。实际模型数字必须以配置文件核对：部分模型的视觉 token 在 prefill 前合并，且权重/视频缓存与其他并发请求也占显存。

6.2 量化、批处理与缓存的适用边界

量化减少模型权重与可能的 KV 显存，但不必然减少图像预处理时间或视觉 token 数；视觉编码器、连接器和 LLM 可分别量化，先做原精度 → 量化同输入配对回归，尤其关注小字、图表数字、颜色、区域指代和多帧顺序。任何“INT4 仅下降 x%”都必须在指定模型、校准集、硬件与评测集下实测，本文不虚构通用精度损失。

连续批处理可提高吞吐，但一张超大图会显著拉长某个批次的 prefill，导致小请求排队。可按 Nvisual、文本上下文和输出长度设分级队列；限制单请求最大像素/帧数，提供自动降采样或明确拒绝策略。仅对相同图片内容、相同 processor/视觉权重版本和相同 crop 策略的结果做缓存，不能凭 URL 复用；变更模型后缓存要失效。

expected = grid_t * grid_h * grid_w // (merge * merge)

    generated = model.generate(**batch, max_new_tokens=128, do_sample=False)
answer_ids = generated[:, batch["input_ids"].shape[1]:]
print(processor.batch_decode(answer_ids, skip_special_tokens=True)[0])

7.1 安全边界和多模态注入

截图、网页图像、OCR 文本均属于不可信输入。图像里出现“忽略之前的要求”只能作为被观察的内容，不应当成为新的系统指令。应在模型外层限制工具调用权限、媒体来源、数据流转和敏感输出；模型拒答只能算一层防护。若评测使用自动裁判，需要抽检其对反事实图像与细字的判定一致性。

Janus-Pro：生成视觉路径同文字提示与参考图，分别测文本回答质量、图像重建/一致性会回答图像问题不证明生成图像保真；图像好看也不证明可定位证据。[33]

7.3 下一步技术难题

长视频的帧选择与时间定位、文档小字的压缩损失、真实视觉依赖而非语言先验、输出中可验证的证据引用，是比单一榜单更贴近生产的问题。图文混排和视频生成还涉及忠实性、组合性、时间一致性与安全风险；无论采用统一模型还是编排多个模型，都应按实际输出模态分别验收，不能用文生视频指标代替视频问答，也不能用 VQA 指标代替视频编辑。[15]

08 /架构师落地路线：最小实验到灰度运行

交付顺序与通过条件（阈值由业务预先填写）
迭代交付物不通过时优先排查
0. 明确范围任务分布、输入尺寸/帧数、质量门槛、TTFT/E2E 和硬件预算缺少代表性数据或最大输入定义，暂停选择模型
1. 建立基线原模型 + 原 processor + 50–200 条人工核验的分层用例；保存原精度模板、图像加载、坐标变换与语言先验偏差
2. 小规模适配冻结桥接或 LoRA 试验；同种子数据版本；记录训练/验证曲线label mask、错位、重复样本、视觉瓶颈
3. 体系化训练多任务混合、压力集、文本回归、完整权重/processor 发布包样本/视觉 token 分布、packing、全参数训练不稳定
4. 灰度和复盘质量 + 延迟 + 成本三维报告；失败样本复核；回滚版本输入上界、资源竞争、量化回归、安全边界

一个具体选型例子：发票/合同理解

先抽样统计长宽比、小字高度、页面数和关键信息位置，构建票据数字、跨页引用、金额单位、空白字段四类用例。选两个模型，在相同预处理和同一 GPU 上画出“字段准确率—视觉 token—p95 延迟”的三维对照。若文本字段准确率低但区域裁切后显著改善，优先改裁切/动态分辨率；若换图仍给同一答案，先查图像路由/训练标签；若视觉准确但 p95 高，控制图片最大像素、分离重请求队列。这个流程是工程建议，不是论文实测结果。

输出与维护契约

上线交付至少包含：模型权重与 license、processor/tokenizer 与 chat template、输入限制、提示模板、推理精度、训练数据清单和授权记录、评测集版本、灰度阈值、监控面板、回滚动作。复盘时按版本比较 OCR、定位、多图时序、文本退化和输入安全的分层变化，而不是只有一个“综合分”。
