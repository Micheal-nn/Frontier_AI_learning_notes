先把“模型在做什么”想清楚

如果你第一次接触大模型，先不要背 Qwen3、CSA、KDA 这些名字。先建立一条可追踪的数据流：文字/图片 → 数字向量 → 多层 Transformer → 下一 token 概率。

读者目标：读完本节，你应该能解释一个 token 在模型里如何变成 hidden state，Q/K/V 如何决定“看谁”，FFN/MoE 如何完成“加工”，KV cache 为什么能加速生成，以及为什么不同模型只是在这些位置替换了模块。

1. Token：模型看到的最小单位

Tokenizer 把文本切成 token id。例如“北京”可能是一个 token，也可能被拆成多个子词。id 只是整数，Embedding 把它查表为向量：x∈Rd。

2. Hidden state：逐层加工后的表示

一段长度为 L 的输入，进入模型后通常表示为 H∈RL×d。每一层都让每个位置获得更多上下文信息。

3. 输出：不是“直接生成一句话”

LM Head 把最后位置的 hidden state 映射到词表大小 V 的 logits，再经 softmax 得到下一个 token 的概率分布。

用一个 token 走完一层 Transformer

  1. 输入：第 i 个位置有向量 hᵢ。
  2. 注意力：由 hᵢ 产生 query，与历史位置的 key 比分；再用分数加权 value。
  3. 残差：把注意力结果加回原表示，避免每层都丢掉已有信息。
  4. FFN：对每个位置单独做更宽的非线性变换；MoE 只让少数专家处理该 token。
  5. 下一层：重复上述过程，直到最后一层。
Q = HWQ，K = HWK，V = HWV
Attention(Q,K,V) = softmax(QKT√dk)V

初学者可以先把 Q 理解为“我想找什么”，K 理解为“我有什么标签”，V 理解为“被找到后提供什么内容”。

训练阶段：一次看完整段文本

训练时用位置 t 的输出预测 token t+1（标签相对输入左移，或等价地将 Decoder 输入右移）；模型并行计算所有位置的 next-token loss。因果 mask 保证位置 i 看不到未来 token，避免作弊。

推理阶段：一个 token 接一个 token

Prefill 先处理整段 prompt；普通自回归 Decode 只处理新 token。注意力层保留历史 K/V，线性注意力层则保留递归状态；混合模型需同时管理两类状态。

算法工程师要会估的 3 个量

全量注意力：近似 O(L²·d)；KV cache：近似 2·L·nkv·dhead·bytes；MoE：总参数可很大，但每 token 只计算 Top‑K 专家。

总参数 ≠ 激活参数

“428B/23B active”表示权重总量约 428B，但一个 token 实际经过的专家与共享层只对应约 23B 的计算路径。显存仍需考虑权重驻留、分片或 offload。

看论文和 config 的分工

论文回答“为什么这样设计”；config 回答“公开权重实际用了多少层、多少头、多少专家”。两者冲突时，必须把口径差异写出来。

01 / COGNITIVE MAP

五类信息，而不是五个串行算子

先固定①输入、②序列混合、③通道混合、④残差/Norm、⑤输出的分类。具体计算从底部向上；④包围②和③。

① 输入表示

文本 ID 查 Embedding；多模态用视觉 encoder / projector 产生替代占位 token 的表示。RoPE 作用在 attention 内的 Q/K，不能画成通用“Embedding + RoPE 向量”。

② 序列混合

GQA 共享 KV；MLA 压缩 KV 表示；CSA/DSA/MSA 选择历史位置或块；KDA / GatedDeltaNet 用递归状态。它们不是一条必然依次升级的技术链。

③ 通道混合

Dense FFN 与 MoE 都处理每个 token 的特征。需区分 Dense 例外层、路由专家、Top‑K、共享专家；潜空间 routed 分支与共享分支可能维度不同。

④ 残差 / Norm

普通 Add、mHC 多流混合、AttnRes 历史块聚合是不同计算；Norm 的类型、位置和参数化也要跟随代码，不能统一用一只“Residual + Norm”框代替。

⑤ 输出与辅助路径

末端表示经 LM Head 变成 logits。MTP 是额外预测目标/模块；只有配合草稿、主模型验证及后端实现时才形成推测解码，不能看到 MTP config 就声称已启用。

基准参照

注意力

每个 token 对可见历史 token 计算相关性。全量注意力的训练计算/注意力矩阵随序列长度近似二次增长。

FFN

逐 token 的通道变换；参数量与计算通常占大头。MoE 用稀疏路由把“一个大 FFN”改成专家池。

残差与归一化

维持深层网络的信息与梯度流。新模型已开始将这部分从固定加法改造成可学习的跨层混合。

Hidden state xₗ 对应哪里？

它不是原始 Transformer 中某一个单独的“Encoder 框”。第 0 层的 x₀ 是输入表示（token embedding，及模型实际采用的模态/位置处理）的输出；第 l 层的 xₗ 是前一个现代 Decoder Block 的输出，代表“当前层开始处理的 token 表示”。RoPE 模型一般在注意力内部对 Q/K 施加位置旋转，并非对 embedding 直接相加。

原始 Encoder 的功能去了哪里？

在 decoder-only 中，prompt 与输出序列拼接后进入同一个因果主干。Prefill 时每个输入位置在 causal mask 下读取左侧上下文，逐层形成上下文化 hidden states；这就是输入编码，只是没有独立的双向 Encoder 堆叠。

为什么现代 LLM 没有 Cross-Attention？

原始 encoder-decoder 把 source 和 target 分开，Decoder 需要 Cross-Attention 从 Encoder 输出取 K/V。decoder-only 把 prompt 和待生成文本放在同一序列里，Self-Attention 已经能读取 prompt 的历史位置，因此通常不再单独画 Cross-Attention。

一句话记忆：原始架构是“Encoder 先读 source，Decoder 再通过 Cross-Attention 取 source”；现代 decoder-only 是“把 source 放进同一条序列，先用 prefill 读完，再从最后一个位置继续生成”。DeepSeek‑V4.1 的论文使用 causal encoder–decoder 术语，但已核查的参考 forward 在两种阶段均遍历 40 层，不应由名称推断生成只经过后半层。
对应原始定义：Attention Is All You Need §3.1–3.2；现代实现参考 Llama modeling code；V4.1 的具体执行见模型章节。

为什么 decoder-only 居多？Encoder 的输入去了哪里？

每层 Causal Self-Attention 与状态本次 query 长度约 P，构建该层历史 K/V；因果 mask 阻止读取未来。普通自回归每请求本次 query 长度约 1，读取已有 P + t 位置的缓存，追加该新 token 的 K/V。t 指此前已被模型处理的生成 token 数。
Token Embedding 与输入输入提示词 x₁…xₚ（可分块 Prefill），生成第一个 token 前已处理完整 prompt。输入前一步刚采样但尚未写入缓存的新 token；无需把整段 prompt 重新送入该请求的 forward。
位置结论：Prefill 与 Decode 都覆盖图中①到⑤的完整前向路径；它们是同一模型的两种调度/序列长度状态，而不是分别归入底部“Encoder”与顶部“Decoder”。KV cache 位于每层 Attention 的侧边，负责在两阶段之间交接历史；普通残差连接不能替代缓存。这个说明针对因果自注意力基线，KDA 等状态型层应改读写递归状态。

decoder-only 为什么常见

  • 目标统一：预训练、指令、推理、工具调用都可写成 next-token prediction。
  • 数据统一：无需为每个样本准备严格的 source→target 对。
  • 缩放简单：所有参数服务于同一自回归路径，训练与部署栈更统一。
  • 生成天然匹配：KV cache、连续批处理、推测解码都围绕单向生成优化。

没有文本 Encoder，输入怎样处理

  • 提示词先经 tokenizer 与 embedding 变为 token 序列。
  • Prefill 时，同一 decoder 对整段提示并行计算，但使用 causal mask：第 i 个位置只能看 ≤i。
  • 每层产生上下文化表示并写入 KV/递归状态；生成从最后一个提示位置继续。
  • 所以它完成了“输入编码”，只是编码器与生成器参数共享、可见性是单向的。

什么时候 Encoder 仍然重要

  • 原始 seq2seq：翻译、摘要可用双向 encoder + cross-attention decoder。
  • 多模态：ViT/音频 encoder → projector → 视觉/音频 token → LLM。
  • 非对称长输入：DeepSeek‑V4.1 的论文使用因果 Encoder–Decoder 分工术语，但公开参考 forward 对 prefill 和 decode 都遍历全部 40 层；跨层共享的是压缩 KV / 索引，不能理解为生成时只跑后 20 层。
  • 检索系统：独立 embedding encoder 负责向量召回，生成模型仍可 decoder-only。
关键辨析：“decoder-only”不等于“没有编码过程”；它只表示没有独立的双向文本 encoder 与 cross-attention 桥。多模态模型即使语言骨干是 decoder-only，也通常仍保留视觉/音频 encoder。

GQA：分组共享 K/V

所在模块：② 序列混合 / 头组织

基线问题：MHA 每个 Q head 都保存独立的 K/V，长上下文解码时缓存与带宽随历史线性增长。

输入 → 处理 → 输出：H 同时投影出 hq 组 Q、hkv 组 K/V；hq>hkv 时一组 Q heads 使用同一个 K/V head，各 Q 仍分别算 softmax 和输出。单层常规 KV 缓存约 2×B×L×hkv×dhead×bytes，不含对齐、量化元数据和索引。

MKV/layer ≈ 2 · B · L · hkv · dhead · bytes
单层常规 KV 张量的理论量级；2 分别对应 K 和 V。

解决的问题与工程代价：减少每历史位置的 KV 宽度，但没有缩短历史，不能声称注意力变成线性时间；更少 KV heads 也减少了独立表示容量。服务端需兼容 head 分组与张量并行。

记忆边界：Qwen3 的 64 Q / 4 KV 见本型号配置。

原始论文或官方报告：GQA；型号层表见代码核查表。

QK‑Norm：约束注意力打分尺度

所在模块：② 序列混合 / Q、K 投影之后

基线问题：Q/K 范数变化会改变 QKᵀ logits 的尺度，使 softmax 过尖或训练不稳；残差主链的 Norm 无法替代内部归一化。

输入 → 处理 → 输出：H→Q/K 投影→按 head 对 Q/K 归一化→按实现施加位置旋转与缩放→因果打分→softmax→加权 V。Qwen3 在 Q/K 上使用 RMSNorm；是否对两者均使用可学习缩放、与 RoPE 的先后须按具体代码判断。

解决的问题与工程代价：只稳定打分，不会减少 KV 容量或改变 causal 可见性；增加 Norm 算子与融合要求。不能把 QK‑Norm 误画成残差的 input_layernorm。

记忆边界：Qwen3 注意力内部创新，不是第五个串行主干阶段。

原始论文或官方报告：QK‑Norm；型号层表见代码核查表。

MoE：用 Top‑K 专家替换逐 token FFN

所在模块：③ 通道混合

基线问题：Dense FFN 参数扩张会让每个 token 都执行全部乘法；需要更大容量但不希望激活计算按总参数同比增长。

输入 → 处理 → 输出：同一个 x 进入 router 和可能存在的 shared 分支；router 选择 routed experts 的 Top‑K，按路由权重汇总输出，若有 shared expert 再汇合；外层 block 随后执行自身残差更新。

y = ∑e∈TopK(x) pe(x) Ee(x) + S(x)
只有型号含 shared expert 时才有 S(x)；其门控和权重归一化须按实现确定。

解决的问题与工程代价：容量和激活计算解耦，但总权重仍需放置/分片，带来专家 All‑to‑All、负载不均、容量规划与冷热专家通信。Qwen3 无 shared；Qwen3.8‑2.4T 有 sigmoid 门控 shared；Kimi routed 分支工作在 latent 空间。

记忆边界：Top‑K 代表每 token 激活数，不是模型一共只有 K 个专家。

原始论文或官方报告：MoE；型号层表见代码核查表。

MLA：压缩每个历史 token 的 KV 表示

所在模块：② 序列混合 / KV 表示

基线问题：GQA 降低头数后，历史仍增长；希望进一步减少每历史位置保存的 KV 字节数。

输入 → 处理 → 输出：H 经低秩投影得到共享 latent KV，并单独处理位置相关分量；缓存紧凑 latent，解码时通过矩阵吸收或投影完成头级计算。它仍可看全部历史，不等于 Top‑K 检索。

解决的问题与工程代价：缓存表示宽度降低，但投影/位置分量拆分、prefill 和 decode 的内核更复杂。是否省内存取决于 latent 宽度、缓存精度与并行方式；GLM 旗舰还叠加 DSA 稀疏选择，不能把两者混为一谈。

记忆边界：牢记“压缩表示”与“减少读取条目”是两个维度。

原始论文或官方报告：MLA；型号层表见代码核查表。

CSA / HCA：本地滑窗加压缩全局历史

所在模块：② 序列混合 / 压缩全局 KV

基线问题：全量未压缩 KV 的长期存储/读取昂贵，只有滑窗又会遗忘远处证据。

输入 → 处理 → 输出：同层并存近期 SWA KV 与压缩全局条目。V4 配置中 CSA 用较低压缩率 r=4 并由 indexer 选压缩条目；HCA 用更强压缩 r=128 读取高度压缩历史，不是先执行 CSA 再执行 HCA。层表决定本层采用哪种压缩策略。

解决的问题与工程代价：本地细节与全局概览互补，代价是压缩器、索引器、异构缓存和稀疏 kernel；HCA 可能丢细节，CSA 索引可能漏召回。不能由压缩率单独推断准确率。

记忆边界：Flash 与 Pro 的层表、Top‑K 不同，见各自配置。

原始论文或官方报告：CSA / HCA；型号层表见代码核查表。

CSA2：跨层共享压缩 KV 与索引

所在模块：② 序列混合 / 跨层缓存

基线问题：如果每层都重新生成压缩 KV 与候选索引，长 Prefill 和持续缓存仍然很贵。

输入 → 处理 → 输出：指定 KV source layers 构造可复用的压缩历史，index source layers 构建或更新索引，其他层重用；当前层仍用自己的 Q 与本层局部 SWA 读取共享全局上下文。具体 source 层号由 V4.1 config 指定。

解决的问题与工程代价：减少重复构建，换来跨层状态依赖、缓存生命周期与重索引正确性。FP4 KV、bounded replay 是相关但独立机制；官方参考 forward 的 prefill/decode 都遍历主干 40 层。

记忆边界：不是原始 Transformer 的双向 Encoder→逐层 Cross‑Attention。

原始论文或官方报告：CSA2；型号层表见代码核查表。

KDA / GatedDeltaNet：递归状态混合

所在模块：② 序列混合 / 长序列状态

基线问题：普通 KV 缓存随历史长度增长，长 Decode 的存储和读取压力持续积累。

输入 → 处理 → 输出：由 x 计算 Q/K/V 和门控；根据当前 K 对旧状态读取的预测误差进行 delta rule 写入，并按门控衰减旧状态，再用 Q 读新状态。可理解为 errorₜ=vₜ−Sₜ₋₁ᵀkₜ，Sₜ≈αₜSₜ₋₁+βₜkₜerrorₜᵀ；仅为教学伪式，不等于具体 kernel。

解决的问题与工程代价：递归状态大小可不随 token 数线性增长，但可能损失对某个旧 token 的精确定位，因此常与 full/MLA 层混排。Kimi KDA 与 Qwen GatedDeltaNet 同属状态型方案，门控、短卷积和更新规则并不相同。

记忆边界：混合模型须同时管理递归状态与全量层 KV。

原始论文或官方报告：KDA / GatedDeltaNet；型号层表见代码核查表。

MSA：索引先选块，主分支再精算

所在模块：② 序列混合 / 块稀疏

基线问题：GQA 仍可能每步读取很长的历史 KV；希望只计算与当前 Query 最相关的历史块。

输入 → 处理 → 输出：KV 按 token 位置分块；轻量 Index Branch 为每个 GQA group 评分选 Top‑K；Main Branch 对被选中块的原始 KV 执行精确 softmax。M3 配置为 128-token 块，Top‑16 包含本地块；Indexer 无独立 V 输出或残差主路。

解决的问题与工程代价：减少每步读取与计算，但主 KV 存储不等于仅剩 16 块；需要索引训练、gather、分页缓存与稀疏内核，误选块会漏信息。与 CSA 压缩后选条目不同，MSA 主分支对所选原始 KV 精算。

记忆边界：“深度块”属于 AttnRes，MSA 选的是序列 KV 块。

原始论文或官方报告：MSA；型号层表见代码核查表。

mHC：在多流残差上做受约束混合

所在模块：④ 深度/残差信息流

基线问题：普通残差以固定单位权重累加子层输出；直接增加多条连接又可能放大信号、损害深层训练稳定性。

输入 → 处理 → 输出：层间持有多流 X；pre 将多流投影为单流 x 供 Norm 和 Attention/FFN；post 将子层输出写回各流，comb 混合旧 X（受 Sinkhorn 类约束）。Attention 与 FFN 各走一次；V4.1 Single‑Pass 复用先前子层传来的 pre_mix。

解决的问题与工程代价：学到跨流路径并控制增益，但多流激活、FP32 混合矩阵和额外通信都有成本。不能把图中 mHC 写成普通 residual+x，也不能把 V4 与 V4.1 的 pre 计算时序合并。

记忆边界：V4/GLM Flash 四流为各自型号配置，不是 mHC 的固定常数。

原始论文或官方报告：mHC；型号层表见代码核查表。

AttnRes：沿网络深度读取历史块

所在模块：④ 深度/残差信息流

基线问题：Pre‑Norm 普通残差一直以固定系数累积历史层，早期贡献可能被深层新输出稀释；直接保存所有层又太贵。

输入 → 处理 → 输出：Block AttnRes 把“层”分成块，保存历史块的表示；在 Attention 和 FFN 前依据当前状态为历史块计算权重并聚合；更新 prefix_sum，在块边界加入历史，末端还有 Output AttnRes。Kimi 的 block_size=12 表示层块，不是 token KV 块。

解决的问题与工程代价：深度方向选择信息，不会替代时间方向的 KV cache；保存历史块、计算权重与跨层传输都增加成本。MSA 沿序列选择，AttnRes 沿层选择，两个“块”不可混写。

记忆边界：Kimi K3 对应实现见本节后方模型图。

原始论文或官方报告：AttnRes；型号层表见代码核查表。

MTP / DSpark：辅助多步预测与草稿验证

所在模块：⑤ 输出相关的辅助路径，而非必经 LM Head

基线问题：普通自回归一轮只扩展一个 token，延迟由串行轮数限制；模型也可加入预测更远 token 的辅助训练信号。

输入 → 处理 → 输出：训练时辅助层根据主干 hidden 与条件 token 预测未来位置并计算损失。只有推测服务启用时，草稿器才先提出候选，主模型一次验证连续前缀并处理回退。V4.1 的 DSpark 独立 forward_spec 读取特定主干层表示，普通 forward 仍给主 logits。

解决的问题与工程代价：潜在减少主模型串行轮次，收益取决于草稿成本、接受率、验证批量与缓存回滚；config 声明 MTP 只证明模块存在，不证明当前后端已开启推测解码。

记忆边界：不能画成 FFN→MTP→LM Head 的串行必经路径。

原始论文或官方报告：MTP / DSpark；型号层表见代码核查表。

11 / ENGINEERING

架构差异如何传导到部署

架构图不是装饰：每个结构选择都会改变 KV/状态管理、并行拓扑、内核需求和容量估算方法。

Qwen3：成熟路径

  • GQA 的 KV cache 易按常规公式估算。
  • 关键瓶颈是 MoE All‑to‑All 与专家权重带宽。
  • 适合优先验证 TP/EP 组合、专家负载与长上下文外推配置。

DeepSeek‑V4：异构 KV

  • CSA/HCA/SWA 产生不同形态的缓存条目。
  • 分页缓存需理解压缩块与稀疏索引。
  • mHC、分组输出投影、Hash 路由都要求专用实现。

DeepSeek‑V4.1：跨层状态共享

  • 按 KV / index source 管理共享缓存与更新依赖。
  • 当前参考 forward 遍历 40 层；不能据 CED 名称直接承诺只执行 20 层或可无修改独立扩缩容。
  • Engram 条件记忆表与视觉入口需另计权重、状态和数据处理成本。

Kimi / GLM Flash：状态型注意力

  • KDA 解码保存递归状态，而非仅保存标准 KV。
  • 前缀缓存需要状态边界感知。
  • 混合层调度、AttnRes/mHC 与多模态编码器增大框架适配面。

MiniMax M3：块稀疏内核

  • 缓存本身仍是 GQA KV，索引结果按 query/group 动态变化。
  • 性能依赖 Top‑K、gather 和 KV‑outer kernel 的联合优化。
  • 容量估算要区分完整 KV 存储与每步只读取 Top‑16 blocks。
验收边界：本文仅完成公开架构与配置的静态核验。未下载模型权重、未运行 GPU 推理，也未测量吞吐、TTFT、TPOT、显存或通信开销；任何性能结论都应在目标硬件、框架版本和上下文分布下重新验证。
